## 2. 本机的反常现象与服务器上的可证伪预测

服务器上的基准：f_sel=0.637，串行跑完 Q=1024 需 902.6 ms。batch=1 时的 Amdahl 上界为 1/(0.637+0.363/16) = 1.52。

| # | 本机现象（来源） | 待检验的硬件解释 | 服务器上的预测（判定标准） |
|---|---|---|---|
| H1 | 并发减速：omp1 在 b=64、p=16 时，各线程工作时间之和是串行的 1.84–2.0 倍，线程速度 max/min 为 1.3–1.7，S=7.4（实验 A 和统计构建） | P/E 核、全核睿频、SMT | 工作时间之和与串行之比 ≤ 1.25，线程速度 max/min ≤ 1.15，S(16) 在 10–13 之间（快速计时已得 11.1） |
| H2 | batch=1 时空转线程拖慢计算线程：每查询计算 542 µs，串行为 371 µs（A_wait） | 自旋线程占用了睿频和 SMT 资源 | omp2 在 b=1、grain=4096、p=16 时，每查询计算时间与串行相差 ≤ 10%；omp2 在 b=1、p=16 时 S ≥ 1.2，接近上界 1.52 |
| H3 | 实验 B：单 batch 时排序让 static 慢 10–16%，模型预测 27–35%；多 batch 时模型预测快 7%，但没有测出来 | 线程速度的差异掩盖了工作量分布的差异 | 单 batch 时 asc/orig 与模型值相差 ≤ 7 个百分点；多 batch 时 asc 比 orig 快 ≥ 4%，且 3 轮方向一致 |
| H4 | SIMD 在 p=16 时只快 1.04–1.14 倍，读带宽已达峰值的 82–93%（实验 E） | 笔记本的内存带宽低（约 37 GB/s） | 若服务器读带宽峰值 ≥ 60 GB/s，则 p=P 时 simd32 的收益 ≥ p=1 时收益的 70%；p=1 时仍受 Amdahl 限制，nprobe=8 时 ≤ 1/0.637 = 1.57 |

## 3. 先确定服务器的 P（S1，检查点 CP-S1）

- **为什么要先做**：lscpu 显示 32 核×1 线程，但物理的 Gold 5218 是 16 核 32 线程，所以这是虚拟化后的拓扑。题目规定大 batch 取 4P：P=16 时为 64，与本机相同，可以直接对比；P=32 时为 128。
- **探针**：用一个只受计算限制、数据在缓存内的负载。omp1，nprobe=1（中心选择占 93%，2 MB 的中心常驻缓存），batch=128，p∈{8,16,24,32}，跑 3 轮。另外用统计构建测 p=16 和 p=32 时各线程的工作时间之和。
- **判定规则**：若 S(32)/S(16) ≤ 1.35，或工作时间之和在 p=32 时比 p=16 时多 40% 以上，说明这些 vCPU 是成对的超线程，P=16；否则 P=32。
- 同时建议用户向助教确认实际分配的物理核数。
- **CP-S1**：用户确认 P 之后再继续。

## 6. 共享服务器的噪声控制

- 服务器上常有 20–40 个用户登录，负载在 0–4 之间波动。应对办法：
  - 每个进程启动前做负载门控，并记录 `load1`；
  - 每一轮内配置随机排序，S4 用区组设计；
  - 某一轮的轮间差超过 10% 就补跑这一轮，并在日志中记下原因。
- 不用 `nice` 降低优先级，以免影响计时。实验按顺序跑，不并发，避免占满整台机器；p=32 只在 S1、S2（且 P=32 时）使用。
- 选在低负载时段运行。如果负载长时间高于 2，就暂停并告知用户。
