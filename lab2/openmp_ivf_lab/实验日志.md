  - 补齐后共 168,280,445 字节，md5 为 b23d1b3b2ee8469d819b61ca900ef0ed，`gzip -t` 校验通过。
- 环境：`lab2/.venv` 中装有 faiss-cpu 1.15.1、numpy 2.5.4、pandas 3.1.1、matplotlib 3.11.2。
- 脚本运行 1 分 28 秒，峰值内存 1.9 GB。结果：
  - **坐标**：库向量在 [0, 218]，查询在 [0, 184]，全部是整数。距离上界 d·M² = 128×218² = 6,083,072 < 2²⁴，所以 float32 精确的前提成立。
  - **训练**：`IndexIVFFlat(IndexFlatL2,128,4096)` 在全部 1M 库向量上训练，用时 55.1 s。参数为 faiss 默认值：niter=10，seed=1234，nredo=1，max_points_per_centroid=256。
  - **列表长度**：最小 66，中位数 227，平均 244.1，p99 558，最大 1255，没有空列表。
  - **gt**：faiss 精确搜索取前 1001 个近邻，再用 int64 整数距离按 (距离, 编号) 重排，保留前 1000 个。faiss 的 float 距离与整数距离的最大误差为 0。有 760 个查询在第 1000 名和第 1001 名处等距。
  - **与公开 gt（前 100 名）比较**：
    - 4446 个查询完全一致；
    - 111 个查询的近邻集合不同，全部可以用等距解释；
    - 5554 个查询集合相同但顺序不同，经核实公开 gt 在这些查询上都按精确距离非降排列，差异只在等距组内部。
  - **等距很常见**：前 100 名内至少有一对等距的查询有 7595 个（占 76%）。等距在真实数据上是常态，不是边界情况。
- 检查：`--only exact --queries 8 --mode check` 的 Recall@10 恰好等于 1.000000，说明自建 gt 和本实验的等距规则一致。

### 实现

- `ivf_simd.cpp`：`l2_distance_f32`（float 累加，没有 omp simd）、`l2_distance_simd64`、`l2_distance_simd32`，以及判断 float32 是否精确的 `f32_distance_exact`。
- `ivf_student.cpp`：
  - omp1：`parallel for schedule(runtime)`，线程团队大小为 min(p, count)。
  - omp2：`parallel` + `single` 为每个查询生成一个任务；查询任务内用 taskloop 分块，每块维护局部 Top-k，taskloop 的隐式 taskgroup 结束后合并；`--coarse split` 时把中心距离的计算也拆成任务。
  - omp3：反面对照，每个候选都在 critical 中更新共享 Top-k。
  - std::thread：划分方式与 libgomp 的 static 相同。
- `ivf_lab.cpp`：
  - 新增参数 `--dist/--sched/--coarse/--cutoff/--order/--perf-ctl/--stats-csv/--profile-csv`，以及 `--mode profile`；
  - CSV 新增开关取值和派生统计列；
  - 串行参考和 check_result 没有改动。
- 编译中遇到的问题：统计构建里 `default(none)` 要求把全局数组 `stats::slots` 写进子句，导致报错。改为通过 inline 函数 `stats::slot(tid)` 访问后解决。

### 向量化证据（`bash scripts/vecreport.sh` → `results/vec/summary.txt`）

- 默认选项（x86-64 基线，SSE2）：
  - 公共 `l2_distance_scalar`（double）没有向量化，诊断为 `missed: couldn't vectorize loop`，只有 `subsd/mulsd/addsd`。
  - **`l2_distance_f32` 没有 omp simd，GCC 仍然向量化了**："loop vectorized using 16 byte vectors"。`subps/mulps` 是打包指令，加法仍是按原顺序执行的标量 `addss`（保持顺序的归约），所以没有违反 IEEE 语义。这正是题目提醒的"去掉 omp simd 后仍可能自动向量化"。
  - simd64 主循环使用 `subpd/mulpd/addpd`；simd32 主循环使用 `subps/mulps/addps`。
- `-march=native`（alderlake）：simd64 和 simd32 都使用 ymm（32 字节向量）；f32 的加法仍是标量（`vfmadd231ss`/`vaddss`）。
- GCC 一次只接受一个 `-fopt-info` 输出文件，脚本改为分两次编译。
