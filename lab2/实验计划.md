## 2. ALU 设计（交付文件 `lab2/src/alu.v`，单文件，第一行 `` `timescale 1ns / 1ns ``）

- **复用加法器**：`cla4`、`cla_unit4`、`cla16` 原样搬过来。顶层的 `adder` 改写成 `cla32(a, b, cin, sum)`，其中 `c16 = gg_lo | (pg_lo & cin)`，把原来写死的 `c0 = 0` 换成真正的 `cin`。
- **四种加减共用一个 CLA**：`sub = (Op==SUB)||(Op==SUBU)`，`b_eff = B ^ {32{sub}}`，`cin = sub`。
- **溢出**：`Over = (A[31]==b_eff[31]) & (sum[31]!=A[31])`，只在 ADD/SUB 时输出，ADDU/SUBU 恒为 0。报告里写两点：
  - 用最高位的真值表证明这个式子等价于 c31⊕c32；
  - 必须用"`b_eff` + `cin`"一步算，不能先求 `~B+1` 再相加。后一种写法在 B=0x80000000 时会判错溢出，对应变异体 M4。
- **移位和逻辑运算**：放在 `always @(*)` 的 `case(Op)` 里用运算符实现，移位量只取 `A[4:0]`。SRA 写成**单独一个分支** `C = $signed(B) >>> A[4:0];`。不要把它和 SRL 合进同一个三目表达式：三目运算符的另一支是无符号数，会让 `>>>` 退化成逻辑右移，对应变异体 M6。
- **默认值**：always 块开头先写 `C = 0; Over = 0;`，这样不会综合出锁存器。未定义的 Op 输出 0/0，作为设计约定写进报告。
- Op 用 `localparam` 起名（ADD=6'b100000 …），不直接写魔数。

## 4. 激励强度实验（延伸部分）

### 4.1 盲区证明（报告里写半页）

ADD 段的操作数形如 `ii<<i`、`jj<<j`，ii、jj ≤ 15，也就是说 A 和 B 的非零位各自落在一个 4 位窗口里。

要让组 k 收到进位，即 C_k=1，下面必须有某一位 m 同时满足 a_m=b_m=1，所以两个窗口都包含第 m 位，都落在 [m−3, m+3] 范围内。最高位 4k+3 ≥ m+4 已经超出这个范围，两数在这一位都是 0，所以 p_{4k+3}=0，组传播 P_k=0。

结论：**ADD 段里 P_k·C_k 恒为 0**。16 位那一层的 `pg_lo·cin` 也一样，因为 ADD 时 cin=0。ADDU 段的窗口只有 2 位，更不可能。

反过来，SUB 的第一个向量 0−0 实际算的是 0 + 0xFFFFFFFF + 1，进位要穿过全部 32 位。整份激励里对 CLA 最强的一次检验，恰好就是 SUB 段的第一个向量。

### 4.2 变异体和预测（计划阶段已用 Python 模型算出，执行时先提交预测，再跑仿真）

| ID | 模拟的典型错误 | 预测：官方激励下首次出错时刻 |
|---|---|---|
| M0 | 沿用旧加法器写死的 c0=0，SUB 时没接 cin | **524,293 ns**（SUB 第 1 个向量 0−0） |
| M1 | `cla_unit4` 的 c[1] 漏掉 P0·cin 项 | **524,293 ns**，整个 ADD 段都能通过 |
| M1′ | 和 M1 一样，但 ADD/ADDU 单独用一个 CLA 实例 | **全程存活**：ADD 和 ADDU 段从不触发这一项 |
| M2 | 顶层 c16 漏掉 pg_lo·cin 项 | **524,293 ns** |
| M3 | `cla4` 的 c[1] 漏掉 p0·cin 项（组内进位） | **2,110 ns**（ADD，0x2+0x1E） |
| M4 | 先求 ~B+1 再相加，用它的符号判溢出 | **525,205 ns**（SUB，0−0x80000000） |
| M5 | 移位量用整个 A，而不是 A[4:0] | **全程存活** |
| M6 | SRA 写进三目表达式，因符号性规则退化成逻辑右移 | **1,653,150 ns**（SRA，0x80000000>>>1） |
| M7 | ADDU/SUBU 也输出溢出 | **1,078,008 ns**（ADDU，0x20000000+0x60000000，该段已跑过 90%） |
| M8 | 把进位输出当成溢出 | **402,302 ns**（ADD，0x08000000+0x78000000，该段已跑过 77%） |

报告里的看点：
- 10 个变异体的死亡时刻从 2 μs 一直分布到"永不"；
- 组间超前进位逻辑只靠 SUB 段的检验才能被发现；
- 只要加法和减法不共用 CLA，官方激励就**完全测不出组间超前进位逻辑是坏的**。

### 4.3 执行步骤

1. `scripts/tb_model.py`（只用 Python 标准库）：
   - 逐个复刻官方激励的向量和时间；
   - 实现逐位的 CLA 模型，带变异开关；
   - 输出 `results/predictions.csv`，以及覆盖统计：各段 P_k·C_k 的触发次数、最长进位链的分布。
2. 把预测**单独提交一次**（git 时间戳证明是先预测、后实验），同时记进实验日志。
3. `scripts/mutate.py`：
   - 对 `src/alu.v` 做"原文 → 替换"的字符串替换，生成 `build/mutants/alu_Mx.v`，每处替换都断言恰好匹配一次，交付的源码保持不动；
   - 逐个用"官方激励 + monitor"跑 xsim，结果写入 `results/mutation.csv`；
   - 与预测逐个比对，要求精确到 ns 一致。
4. `sim/alu_tb_plus.v` 增强激励，自检式：
   - 用 `!==` 比较，按运算分别计错，打印前 10 个不一致的向量，最后输出 PASS/FAIL；
   - 向量分五类：
     - ① 边界值全组合：{0, 1, 2, 0x7FFFFFFF, 0x80000000, 0x80000001, 0xFFFFFFFE, 0xFFFFFFFF, 0x55555555, 0xAAAAAAAA}² × 11 种运算；
     - ② 长进位链：A = 2^k−1、B = 1，以及 B = ~A、B = ~A+1；
     - ③ 移位量高位污染：A = {随机[31:5], sa}；
     - ④ 固定种子的随机满位操作数，每种运算 2 万组；
     - ⑤ 抽样未定义的 Op，期望输出 0/0。
   - 目标：正确设计 0 错误，10 个变异体全部被杀，并记下每个变异体是被哪一类向量杀死的。
